# ST Стоматологія — сайт клініки

Статичний сайт приватної стоматологічної студії (Київ). Без збірки, без залежностей у продакшені: чистий HTML + CSS + vanilla JS.

## Файли

| Файл | Призначення |
|---|---|
| `index.html` | Розмітка, мета-теги, Schema.org (`Dentist` + `FAQPage`), SVG-спрайт іконок |
| `style.css` | Уся стилізація, дизайн-токени, адаптив, `prefers-reduced-motion` |
| `app.js` | Каруселі зі свайпом, before/after, скрол-анімації, форма, модалка запису, мобільне меню |
| `api/notify.js` | Serverless-функція (Vercel): приймає заявку з форми і пересилає в Telegram |
| `services/veneers/index.html` | Детальна сторінка послуги «Преміум вініри» — окремий URL, а не якір |
| `services/implants/index.html` | Детальна сторінка послуги «Цифрова імплантологія» |
| `services/smile-design/index.html` | Детальна сторінка послуги «Дизайн усмішки» |
| `sitemap.xml` | Карта сайту для Google — усі 12 сторінок |
| `robots.txt` | Дозволяє індексацію, вказує на sitemap.xml |

## SEO: індексація в Google

Сайт складається з **12 сторінок** з унікальними `<title>`, `meta description` та `canonical` (перелік — у `sitemap.xml`). Перед публікацією:

1. Замініть `st-dental.ua` на ваш реальний домен — і в `sitemap.xml`/`robots.txt`, і в `<link rel="canonical">` та `og:url` кожної сторінки (простіше зробити пошуком-заміною по всіх файлах).
2. Додайте сайт у [Google Search Console](https://search.google.com/search-console) та надішліть `sitemap.xml` вручну (Search Console → Sitemaps) — це прискорює першу індексацію на кілька днів-тижнів замість очікування природного сканування.
3. Перевірте `https://ваш-домен/robots.txt` і `https://ваш-домен/sitemap.xml` у браузері після деплою — обидва мають відкриватися напряму.

## ⚠️ Безпека: Telegram-токен

Форма запису шле заявки в Telegram **через серверну функцію** (`api/notify.js`), а не напряму з браузера. Токен бота зберігається лише як змінна оточення на Vercel і ніколи не потрапляє у фронтенд-код — будь-хто, хто відкриє «Переглянути код сторінки», побачить тільки виклик `fetch('/api/notify', …)`, без токена.

**Якщо токен бота колись засвітився в чаті, коміті, скріншоті тощо — вважайте його скомпрометованим і одразу перевипустіть:**
Telegram → `@BotFather` → `/mybots` → ваш бот → `API Token` → `Revoke current token`.

## Публікація на Vercel (потрібна для форми запису)

Форма записується через serverless-функцію — тому GitHub Pages **не підійде** (це чисто статичний хостинг без бекенду). Використовуйте Vercel:

1. Залийте репозиторій на GitHub (структура файлів має лишитися як є: `index.html` і `api/notify.js` в корені).
2. На [vercel.com](https://vercel.com) → `Add New` → `Project` → імпортуйте репозиторій. Framework Preset — `Other`, build command не потрібен.
3. `Settings` → `Environment Variables` → додайте:

   | Ключ | Значення |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен вашого бота від `@BotFather` |
   | `TELEGRAM_CHAT_ID` | ID чату/каналу, куди слати заявки (див. нижче) |
   | `ALLOWED_ORIGIN` *(опційно)* | ваш домен, якщо форма викликатиметься з іншого джерела |

4. `Deploy`. Через ~1 хвилину сайт і `/api/notify` будуть доступні на `https://<project>.vercel.app`.

### Як дізнатися TELEGRAM_CHAT_ID

1. Напишіть своєму боту `/start` у Telegram (якщо заявки мають приходити особисто вам) — або додайте бота в групу/канал і зробіть його адміністратором (якщо заявки мають приходити туди).
2. Відкрийте в браузері (замініть `<TOKEN>` на реальний токен бота):
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. У відповіді знайдіть `"chat":{"id": ...}` — це число (може бути від'ємним для груп) і є `TELEGRAM_CHAT_ID`.
4. Якщо відповідь порожня (`"result":[]`) — напишіть боту ще одне повідомлення і оновіть сторінку `getUpdates`.

Після редеплою перевірте форму на живому сайті — заявка має прийти в Telegram протягом секунди.

## Публікація на GitHub Pages

1. Створіть репозиторій і залийте ці файли в корінь (`index.html` має бути на верхньому рівні).
2. `Settings` → `Pages` → `Source: Deploy from a branch` → `Branch: main`, папка `/ (root)`.
3. Через 1–2 хвилини сайт буде доступний за адресою `https://<username>.github.io/<repo>/`.

Альтернативи: Vercel, Netlify, Cloudflare Pages — просто вкажіть корінь проєкту, команда збірки не потрібна.

## Локальний запуск

Достатньо відкрити `index.html` у браузері. Або через локальний сервер:

```bash
npx serve .
```

## Дизайн-система

Токени оголошені в `:root` (`style.css`). Змінюйте кольори в одному місці:

```css
--ink:        #0E0D0B;  /* фон */
--ink-soft:   #16150F;  /* фон секцій */
--bone:       #F2EDE4;  /* основний текст */
--bone-dim:   #A39C8E;  /* приглушений текст */
--brass:      #C8A96A;  /* акцент, золото */
--brass-deep: #8C7238;  /* темний акцент */
```

Типографіка: **Instrument Serif** (заголовки) + **Manrope** (текст), підключені через Google Fonts.

## Мобільний UX

- Свайп-галерея та свайп-слайдер відгуків (`scroll-snap` + drag мишкою на десктопі)
- Липка нижня панель «Дзвінок / Записатися», з'являється після геро-секції
- Off-canvas меню зі свайпом вправо для закриття
- Смуга прогресу читання, автоприховування шапки при скролі вниз
- Акордеони для цін і FAQ, `<details>` як основа — працюють навіть без JS
- Розмір шрифту в полях форми 16px, щоб iOS Safari не зумив сторінку
- Підтримка `env(safe-area-inset-*)` для iPhone з вирізом
